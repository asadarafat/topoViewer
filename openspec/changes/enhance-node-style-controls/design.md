## Overview

This change expands TopoViewer node styling where it improves dense topology readability. The public contract stays stylesheet-first, canonical `camelCase`, and renderer-owned. Cytoscape.js remains a reference for useful concepts, not the runtime syntax or exact behavior contract.

Existing node styles must continue to work:

```yaml
stylesheet:
  - selector: node
    style:
      shape: ellipse
      width: 82
      height: 60
      backgroundColor: "#dbeafe"
      borderColor: "#2563eb"
      borderWidth: 3
      labelColor: var(--topoviewer-fg-strong)
```

New controls should compose with the existing flat `style` model rather than introduce nested node style objects.

## Public Contract

Preferred authoring remains:

```yaml
stylesheet:
  - selector: node[labels.role = "aggregate"]
    style:
      shape: roundRectangle
      width: 96
      height: 64
      labelPosition: bottom
      labelTextWrap: wrap
      labelTextMaxWidth: 110
      labelBackgroundColor: var(--topoviewer-panel-bg)
      labelPadding: 4
      borderStyle: dashed
      outlineColor: "#f59e0b"
      outlineWidth: 3
      underlayColor: "rgba(245, 158, 11, 0.16)"
      underlayPadding: 8
      badgeLabel: "42"
      badgePosition: topRight
      statusColor: "#ef4444"
      statusPlacement: bottomRight
```

Do not add a public `nodeStyle`, `labelStyle`, `iconStyle`, or `shapeStyle` object. TopoViewer already has `style`, selector rules, and per-object overrides.

## Label Rendering

The current node label is an HTML element below the icon/body. Keep labels as HTML rather than SVG text. HTML labels preserve safe markdown rendering, links, images, theme variables, and normal browser text wrapping.

Recommended implementation:

1. Compile label position, offsets, wrapping, background, border, padding, opacity, and minimum zoom keys into node data.
2. Use CSS classes plus inline variables/styles to place labels around or inside the node body.
3. Preserve existing safe markdown rendering for `name` and `label`.
4. Keep current label-density and attention label-priority behavior, with new explicit style keys acting as author intent.

Supported `labelPosition` values:

- `top`
- `right`
- `bottom`
- `left`
- `center`

Supported wrapping:

- `labelTextWrap: none` keeps one-line behavior.
- `labelTextWrap: wrap` allows wrapping up to `labelTextMaxWidth`.
- `labelTextOverflow: clip | ellipsis` controls overflow when wrapping is disabled.

`minZoomedLabelFontSize` should suppress a label when the current viewport zoom would make its effective font size smaller than the configured threshold. This should not remove the node from graph layout or focus behavior.

## Border, Outline, And Underlay

Node body geometry currently receives fill, stroke, and stroke width. Extend this paint model without changing the graph hit area.

Recommended layering:

1. Underlay behind the node body.
2. Optional outline behind or outside the node stroke.
3. Node body fill and border.
4. Icon/image/glyph content.
5. Badge and status marker.
6. Label and metadata.

`borderStyle` and `borderDashPattern` should map to SVG stroke dash behavior for the node body shape. `borderOpacity` should affect only the body border, not the icon or label.

`outlineWidth` and `underlayPadding` should expand around the node body visually but must not change React Flow node dimensions, edge anchors, drag handles, or layout inputs. If visual expansion risks clipping, increase internal SVG viewBox padding while preserving the external node bounds.

## Icon And Image Fit

TopoViewer should keep reusable `icons` as the source of icon assets. The node style controls how an icon is rendered inside the body.

Supported values:

- `iconFit: contain` preserves aspect ratio and fits inside the icon box.
- `iconFit: cover` preserves aspect ratio and fills the icon box, clipping overflow.
- `iconFit: fill` stretches to the icon box.

`iconPadding` should shrink the usable icon content box inside `iconWidth` and `iconHeight`. `iconBackgroundColor` should apply to the icon content frame, not the whole node body.

Glyph icons should respect `iconOpacity`, `iconColor`, and `iconPadding`. Image and SVG icons should respect `iconOpacity`, `iconFit`, and `iconPadding`.

## Badge And Status Markers

Badges and status markers should be simple overlays, not full custom widgets.

Supported badge positions:

- `topLeft`
- `topRight`
- `bottomLeft`
- `bottomRight`

Supported status placements:

- `topLeft`
- `topRight`
- `bottomLeft`
- `bottomRight`
- `center`

Badge text should be short and single-line. If `badgeLabel` is too long, the renderer should clamp visually and lint may warn. Badge values can come from:

1. explicit stylesheet style keys,
2. per-object style overrides,
3. aggregate summary metadata generated by attention reduction.

Explicit style keys should win over generated defaults.

Status markers should be color indicators only. They should not introduce a separate severity model in this change. Host applications may continue to map their own `data.*` values to `statusColor` through selectors.

## Attention And Aggregate Integration

Attention aggregate nodes already carry summary information such as member count and severity summary. This change can make those summaries visible by default where appropriate, but should keep the contract conservative:

- aggregate nodes may default `badgeLabel` to hidden member count,
- aggregate nodes may default `statusColor` from worst known severity when available,
- explicit author styles must override generated badge/status defaults,
- non-aggregate nodes must not gain unexpected badges unless styles request them.

## Validation And Lint

Validation should continue rejecting kebab-case style keys. Add semantic lint for:

- unsupported `labelPosition`, `labelTextWrap`, `labelTextOverflow`, `borderStyle`, `iconFit`, `badgePosition`, and `statusPlacement` values,
- negative or non-finite numeric values for padding, opacity, outline, underlay, offsets, and status size,
- invalid opacity ranges,
- malformed `borderDashPattern`,
- suspiciously long `badgeLabel` values,
- use of badge/status keys on selectors where they cannot render.

Runtime should fail soft and preserve a visible graph even when style input is imperfect.

## Examples

Add compact examples under the existing reference examples structure:

1. `nodes/label-placement`: four nodes showing top, right, bottom, center labels, wrapping, and backing.
2. `nodes/border-outline-underlay`: small operational topology showing warning/critical emphasis without changing shape.
3. `nodes/icon-fit-and-badges`: icon fit modes plus short badges and status markers.
4. `attention/aggregate-badge-status` or `nodes/aggregate-badge-status`: collapsed aggregate summary node showing count and worst status.

Each example should include live viewport, topology YAML, stylesheet YAML, and expected assertions. Keep each graph small so the visual effect is obvious.

## Risks

- Label placement can overlap nearby nodes if examples or defaults are too aggressive.
- Outlines and underlays can be clipped if the SVG viewBox is not padded carefully.
- Badges can become unreadable if authors put too much information in them.
- Zoom-aware label suppression must not fight existing attention label-priority behavior.
- Adding many visual controls can weaken the visual language; docs should recommend using these controls for operational meaning, not decoration.
